## 一、总体结论

v1.0.0 宣称的主链路（事实资料 → 岗位画像 → 临时简历 → 转正式 v1 → 工作副本编辑 → 不可变版本 → A4 HTML 导出）**端到端可用**，后端领域模型、版本不可变、回收站、审计记录等核心规则实现质量较好，与设计文档吻合度高。

但**界面层与交互设计书的差距明显**，且存在 1 个已实证的核心状态 bug 和 1 类影响交付物美观的结构性排版缺陷。当前实现大约覆盖交互设计书验收标准的 55%–60%，主要集中在「信息架构骨架」而非「完整交互细节」。

| 维度 | 评价 |
| --- | --- |
| 功能主链路 | ✅ 可用、稳定 |
| 数据/版本/回收站规则 | ✅ 与功能设计书基本一致 |
| 信息架构（首页三入口、模块首页） | ✅ 骨架一致 |
| 交互细节（状态栏、确认、排序、预览控制等） | ⚠️ 大量缺失 |
| 视觉美观 | ⚠️ 底子干净，但简历画布/导出 HTML 有结构性排版缺陷 |
| 文档与实现一致性 | ⚠️ 发布记录与实现有 3 处不符 |

## 二、现状（已实现且验证通过）

### 2.1 后端（app/）

- **数据模型**（`workbench_models.py`）：User/Workspace 隔离、FactRecord + 6 类分类明细表 + 自定义字段 + 审计（FactAudit）、RequirementProfile（含 identity_key 唯一约束与指纹标准化）、JobOpportunity、ResumeIdentity/ResumeVersion/ResumeWorkingCopy、Evidence（校验和、白名单）、PendingItem——与实现设计书第 3 节字段级吻合。
- **版本规则**：转化即建 `format_conversion`（“格式化简历、未润色”）v1；保存追加线性版本；`save` 校验 `base_version_id` 过期返回 409；历史版本只读 + 恢复到工作副本；DELETE 简历仅入回收站——符合功能设计书 6.3 不可违反规则。
- **证据上传**：PDF/PNG/JPEG/WEBP 白名单、10 MB 上限、SHA-256 校验和、内容寻址存储（`main.py:238-249`）。
- **回收站语义**：事实被正式简历引用时删除进回收站，未引用时永久删除（`main.py:200-213`），符合修订绑定规则。
- **来源变化提醒**：事实更新/回收自动生成 PendingItem，保存正式版本后批量 resolve（`main.py:186-191, 411`）。
- 测试：`tests/` 7 个文件 27 项全部通过。

### 2.2 前端（web/src）

- 首页三入口卡片（资料库/岗位画像/ResumeCraft）+ 统计摘要，扁平风格与设计书 3.1 一致。
- 资料库：分类入口总览 + 全局搜索 + 分类页可审阅表格（名称/摘要/证据数/更新时间）+ 回收站，符合 2026-09 绑定修订。
- 事实编辑：按 `/api/fact-schemas/{category}` 动态渲染结构化表单 + 扩展字段 + 证据上传/链接入口。
- 临时简历：初始空白 A4 画布只显示栏目名（符合实施基线）；点击栏目弹出居中选择卡片（搜索/复选/已选计数/背景遮罩），画布实时更新。
- 正式工作区：只读 A4 预览 + 点击条目打开居中编辑卡片 + 右键快捷菜单（编辑文本/添加来源），编辑控件不进纸面，符合修订绑定；工作副本 500ms 防抖自动保存；版本历史面板 + “以 vN 创建工作副本”确认弹窗（区分保留草稿/创建）+ 导出 HTML 下载。
- 响应式：<850px 有降级缩放（虽设计书不承诺窄屏）。

### 2.3 实测通过的关键交互

打开首页 → 资料库分类 → 表格 → 编辑卡片；岗位画像列表 → 创建临时简历 → 空白画布 → 选择卡片勾选 2 条 → 画布即时渲染；打开正式简历 → 点击区块 → 编辑卡片弹层 → 完成关闭；版本历史与底部操作栏渲染正常。

## 三、已实证的缺陷（Bug，建议优先修复）

### P0-1 仅打开简历即被标记为“有未保存修改”（已实测证实）

- **现象**：将 resume 3 的 `dirty` 在数据库清零后，浏览器仅打开该简历、不做任何编辑，约 0.5–2.5 秒后 `PATCH /api/resumes/3/working-copy` 自动触发，`dirty` 变回 `true`，`updated_at` 刷新为当前时间。
- **根因**：`App.tsx:83-84` —— `content` 从服务端载入时 `useEffect([content,id])` 首次触发即执行自动保存 PATCH；前端没有“本地是否真实改动过”的追踪。
- **影响**：① 顶部“工作副本有未保存修改”常驻、状态失真（违反交互设计书 12.1 状态区分）；② 首页“工作副本”统计恒等于“被打开过的简历数”，无业务含义；③ 简历列表 `dirty` 字段永真。
- **建议**：载入后设置 `baseline` 快照，仅当内容与基线不同才 PATCH；或将自动保存改为仅在真实编辑事件后启动。

### P0-2 简历画布与导出 HTML 的栏目标题逐条目重复（结构性排版缺陷）

- **现象**（截图证实，画布与导出 HTML 一致）：“项目与实践”标题出现 3 次（每个条目各带一次）、侧栏“技能”×4、“成果”×2；导出 HTML 中 `<h2>` 序列为 `技能,技能,技能,成果,成果,个人简介,项目与实践,项目与实践,教育经历`。
- **根因**：
  - 前端 `App.tsx:147-163 paginate()` 把每个 block 拆成独立 unit 且每个 unit 携带完整 section 标题；
  - 后端 `services.py:226-235 section_units()` 同样按 block 输出 `<section class="section"><h2>标题</h2>`。
- **影响**：交付物（正式简历 HTML）观感明显不合格——一份简历同一栏目出现多个大标题。
- **建议**：分页时按“栏目→条目”两级聚合：同一栏目的连续 fragment 共享一个 `<h2>`；分页断裂发生在条目之间，续页顶部可重复栏目标题（或加“续”标记），但同页内不重复。

### P1-3 条目标题与“事实来源”标记无间隔粘连

- **现象**：`BlockView` 中 `<b>{title}</b><small>事实来源</small>` 行内相邻，渲染为“越疆 X-Trainer 竞赛与优必选人形机器人挑战赛**事实来源**”，读起来像标题的一部分；临时简历画布中每条都带，视觉噪音更大。
- **建议**：来源标记改为右上角徽标/图标或标题下方独立小字，并与 9.1 的“来源侧栏入口”联动（点击打开来源面板）。

### P1-4 自动保存把“打开”当“编辑”：打开即写入 working_copy

- 与 P0-1 同根因，但另有一层：即使内容无变化，`PATCH` 也会刷新 `updated_at` 并把整份内容写库——频繁打开简历会产生大量无意义写放大。
- **建议**：PATCH 前先比较内容哈希，无变化不发送。

### P1-5 存量工作副本为旧格式，且会被自动保存固化

- **现象**：resume 1 v4 工作副本中 blocks 无 `fields`（字段全部丢失进正文），正文尾部粘连 `brief()` 摘要（如“…训练集过拟合。 · 竞赛 · 实验室小组”、“…操作系统 · 本科 · 数据科学与大数据技术”）。
- **根因**：这批数据由旧版代码生成；当前 `fact_to_block`（services.py:98）已是干净结构，但旧工作副本没有任何迁移/修复路径，而 P0-1 的“打开即保存”反而把旧格式固化。
- **建议**：提供一次性“按 source_refs 从事实库重建工作副本字段”的迁移命令；或在载入时检测无 `fields` 的 fact block 并提示重建。

### P2-6 事实编辑卡片打开时滚动位置错误

- **现象**：打开“编辑资料”弹层时视图直接停在表单中段，标题栏与关闭按钮被滚出视野（autofocus 触发滚动）。用户第一眼看不到自己编辑的是哪条资料。
- **建议**：弹层内滚动容器与 autofocus 顺序调整（先定位后聚焦，或 header 设为 sticky）。

### P2-7 历史回退后的保存原因丢失“rollback”标记

- `restore_version` 把历史内容复制进工作副本，但下一次 `save` 一律记录 `reason="user_save"`（`main.py:409`）。功能设计书 4.8/10.3 要求回退保存标记为 `rollback`。
- **建议**：`restore_version` 在工作副本上记录 `pending_reason=rollback`，保存时消费该标记。

### P2-8 发布记录与实现不符（文档一致性）

1. 发布记录称“导出模板：Jinja2，位于 `app/templates/resumes/`”——实际导出由 `services.py:render_resume_html()` 内嵌 f-string 渲染，`classic.html` 仅被废弃的 `seed.py` 引用，`app/templates/` 其余 11 个 Jinja2 页面全部是无人路由的死代码。
2. 功能设计书 1.1 以 `output/默认简历成品目录/机器人数据采集与数据标注_初版.html` 为视觉基准——该目录在仓库中不存在，视觉基准无从对照。
3. 技术设计书 8 的 `/api/ai/edit`、差异 API、`GET /api/evidence`（全局证据视图）等在“本版本不包含”中未逐一声明（AI/ZIP 已声明，差异比较与证据全局视图未声明）。

## 五、视觉美观专项评价

**好的方面**：整体扁平干净的绿灰色系、Georgia+雅黑混排标题、卡片/表格/弹层风格统一、A4 纸面阴影与深色侧栏的简历版式底子不错，首页观感在同类工具里属中上。

**需要改进（按影响排序）**：

1. 【高】栏目标题逐条目重复（P0-2）——这是“简历好不好看”的第一杀手，画布和导出同时存在。
2. 【高】侧栏在编辑模式下每个栏目标题旁都挂“添加来源”小按钮，深色侧栏上排一排白色小按钮，版面破碎；建议编辑态改为 hover 浮现。
3. 【中】条目标题后粘连“事实来源”小字（P1-3）。
4. 【中】首页统计条是四块连体色块，与上方卡片风格脱节；首页信息密度低，整页重心过高（下方大片空白，正好缺“近期正式简历”内容）。
