## 0. 调查结论（TL;DR）

- 主链路（事实资料 → 岗位画像 → 临时简历 → 转正式 v1 → 工作副本编辑 → 不可变版本 → A4 HTML 导出）**端到端可用**，后端 28 项 pytest、前端 4 项 vitest 全部通过。
- v1.0.1/v1.0.2 发布记录声称的修复经逐项核对**基本属实**（打开即 dirty、栏目标题重复、rollback 原因、来源徽标、Esc 关闭、模板库、Markdown 工具条、待处理跳转定位、质量提示等均已在代码中确认）。
- 但本轮新发现 **2 个 P0 级后端 bug（均可用探针稳定复现）和 1 个 P1 级前端数据污染 bug**，另有若干设计文档要求但未实现的功能缺口与文档自身失真。
- 工作区存在**未提交的 v1.0.2 改动**（5 个文件，+163/-33），发布记录已宣称 v1.0.2 发布但代码从未入库，本次一并提交。

## 2. 已实证 Bug（本轮新发现）

### BUG-1（P0）导出含“链接与作品集”区块的简历必然 500 崩溃

- **位置**：`app/services.py:286`（`esc(url, quote=True)`）；`esc` 定义于 `app/services.py:269-270`，只接受一个位置参数。
- **现象**：只要某个区块的 `fields.url` 有值（`links` 栏目的事实会自动带上），`POST /api/resumes/{id}/versions/{n}/export` 即抛 `TypeError: esc() got an unexpected keyword argument 'quote'`，导出失败。
- **实证**：探针脚本直调 `render_resume_html` 与 TestClient 全链路各复现一次；现有 28 项后端测试未覆盖“含链接区块的导出”，因此逃逸。
- **影响**：核心栏目“链接与作品集”（功能设计书 3.1/4.6）一旦使用，交付物完全无法生成；前端只弹“导出失败”。
- **修复状态**：✅ 已修复（去掉多余的 `quote=` 关键字实参，`esc` 内部本就以 `quote=True` 转义），并补导出回归测试。

### BUG-2（P0）“新简历身份”分叉后，新简历无法打开（GET 500），且首次保存 503

- **位置**：`app/main.py:596-605`（`fork_resume_identity` 不设置 `current_version_id`，符合“首次保存从 v1 开始”的设计）+ `app/main.py:481`（`get_resume` 把可能为 `None` 的 current 直接传给 `serialize_version`）。
- **现象**：分叉成功后打开新简历，`GET /api/resumes/{id}` 在 `serialize_version(None)` 处抛 `AttributeError: 'NoneType' object has no attribute 'id'`，前端 `useLoad` 静默吞错，页面永远停在“正在加载”。
- **实证**：TestClient 复现（convert → fork → GET 崩溃）。
- **影响**：v1.0.2 发布记录宣称的“岗位画像支持新简历身份分叉”实际不可用；列表页同时会把版本号渲染成 `vnull`。
- **修复状态**：✅ 已修复（`get_resume` 对无当前版本的简历返回 `current: null`；前端对 `current_version === null` 显示“未保存”并禁用导出/放弃修改；补分叉全流程回归测试）。

### BUG-2b（P0，随 BUG-2 的回归测试暴露）分叉出的新简历首次正式保存报 503“没有可用模板”

- **位置**：`app/main.py` `fork_resume_identity` 创建的工作副本未继承源版本的模板版本，`save_resume` 在 `latest is None` 分支取 `copy.template_version_id`（None）且无最新版本可回退 → 503。
- **说明**：即使 BUG-2 修复、页面能打开，用户编辑后点“保存正式版本”仍必然失败——分叉功能从入口到保存全链路断裂。
- **修复状态**：✅ 已修复（分叉工作副本继承 `current.template_version_id`，由 BUG-2 的回归测试一并覆盖）。

### BUG-3（P1）正式编辑长正文时，分片重组向正文注入换行符（内容污染）

- **位置**：`web/src/App.tsx:247-251`：`update()` 按 `splitText()` 的固定长度分片编辑后用 `chunks.join('\n')` 还原，而 `splitText` 是按字符位置切分、原文并无换行。
- **现象**：正文超过分片上限（主栏 900 字、侧栏 520 字）时，编辑任意一个片段并触发自动保存，片段边界处会被插入多余的 `\n`。实证：2500 字正文（0 换行）编辑片段 0 一次后变为 2503 字、2 个换行。
- **影响**：违背“临时简历只选择、正式正文独立编辑”的文本保真预期，导出 HTML 与用户预期排版出现莫名断行；长简介/长项目描述是常态，命中概率高。
- **修复状态**：✅ 已修复（`chunks.join('')`，与位置切分严格互逆）。

### BUG-4（P2）首页概览“岗位画像”统计把回收站中的画像也计入

- **位置**：`app/main.py:146`：`overview` 的 `stats.profiles` 无 `status == "active"` 过滤（facts、resumes 均只统计有效记录）。
- **影响**：删除画像进入回收站后首页统计不降，与“资料库/正式简历”口径不一致。
- **修复状态**：✅ 已修复（补充 status 过滤）。

### BUG-5（P3）选择与当前相同的模板也会把工作副本标记为脏

- **位置**：`app/main.py:499-508`：`choose_template` 无条件 `copy.dirty = True`。
- **影响**：点了当前模板一次就出现“有未保存修改”，随后离开确认被无谓触发。
- **修复状态**：✅ 已修复（模板未变化时不置脏）。
